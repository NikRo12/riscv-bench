# Если что-то пошло не так

Первое действие при любой ошибке: открыть лог этапа, имя которого скрипт напечатал в сообщении.

```bash
tail -40 work/logs/<этап>.log          # bootstrap, fetch, patch, build-oneTBB, build-openvino
```

Все эти проблемы реально встречались при создании утилиты.

## На сервере

| Симптом | Причина | Что делать |
|---|---|---|
| `doctor`: `[??] сеть: ... timed out` | адрес отвечает медленно | это предупреждение, сборку оно не останавливает. Скачивание в `bootstrap` ждёт дольше и повторяет попытки (3 раза); если всё же не вышло, проверьте `curl -I <адрес>` и повторите `python3 build.py bootstrap` |
| `doctor`: `HTTP Error 405` для micromamba | старая проверка сети использовала запрос HEAD | обновить код (в текущей версии исправлено) |
| `git: command not found` | на сервере нет системного git | после `bootstrap` наш лежит в `work/toolchain/env/bin`: `export PATH=$PWD/work/toolchain/env/bin:$PATH`. Сам `build.py` справляется без этого |
| `error while loading shared libraries: libisl.so.23` (и `libbfd`, `libopcodes`) | компилятору не хватает x86-библиотек | добавить пакет в `host_debs` в `target.toml`, выполнить `python3 build.py bootstrap`. Не запускайте кросс-GCC вручную без `PATH` и `LD_LIBRARY_PATH` из `ctx.env()` |
| `cannot find /usr/riscv64-linux-gnu/lib/libc.so.6` | компилятору не указан sysroot | собирать только через `build.py` (в toolchain-файле есть `CMAKE_SYSROOT`); при ручной проверке добавьте `--sysroot=work/toolchain/root` |
| `unknown cpu 'spacemit-x100'` | стоковый GCC не знает родное ядро | взять другое значение `tune` в `target.toml` (`sifive-p670`) |
| `apt download`: пакет не найден или другая версия | на сервере другой релиз Ubuntu | в `target.toml` подобрать имена пакетов под `apt-cache policy <пакет>` |
| `patch`: «не ложится на исходники» | версия исходников отличается от той, для которой сняты патчи | сверить `version`/`commit` в конфиге, смотреть `work/logs/patch.log`; патч нужно переделать под новую версию |
| `fetch`: коммит не совпадает с ожидаемым | тег сдвинули или исходники изменены | проверить `git ls-remote --tags`, обновить `commit` в конфиге |
| `build` оборвался без ошибки в логе | кончилась память (OOM) | `dmesg \| tail`, запуск с `--jobs 4`; после этого `build` продолжит с места остановки |
| `build` упал с ошибкой компиляции | смотреть `work/logs/build-<имя>.log` | искать первую строку `error:`; после исправления `build` просто повторить |
| `verify`: `[!!]` на строках патчей, остальное `[ok]` | в бинарнике нет искомой строки | проверить точнее: `riscv64-linux-gnu-nm -C <плагин.so> \| grep -ci <имя>`; если там 0 - патч не вошёл в сборку, если >0 - строку в `[verify]` стоит заменить на имя, которое остаётся в бинарнике |
| `verify`: «требует libXXX, его нет в бандле» | не все библиотеки попали в `[[bundle]]` | добавить маску в `patterns` нужного блока |
| `package`: «нет файлов по маске» | `build` не создал этот файл или неверная маска | `ls` каталога из `src` блока `[[bundle]]` |
| `git push`: `Permission denied (publickey)` | на сервере нет SSH-ключа, известного GitHub | создать ключ и добавить в GitHub как deploy key с правом записи; указать его: `git config core.sshCommand "ssh -i ~/.ssh/<ключ> -o IdentitiesOnly=yes"` |

## На плате

| Симптом | Причина | Что делать |
|---|---|---|
| `cannot open shared object file` | библиотеки бандла не найдены | запускать через `./run.sh` (он ставит `LD_LIBRARY_PATH`); не переносить `bin/` отдельно от `tbb/` |
| Подмешивается старый OpenVINO | в сеансе остались `LD_LIBRARY_PATH`/`OV_BIN` от прошлых экспериментов | новый ssh-сеанс или `unset LD_LIBRARY_PATH OV_BIN` |
| Время около 94 с вместо ~51 с | быстрая реализация свёрток не включилась (нет патчей в сборке) | `verify` на сервере; в плагине должен быть класс `rvv_brgemm_convolution` (`nm -C`); смотреть, что патчи применились |
| Столбцы в `results.csv` пустые, запуск прошёл | регулярка в `metrics` не совпала с выводом бенчмарка | проверить на `results/*/threads_N.log`: `sed -nE 's/.*<регулярка>.*/\1/p' <лог>` |
| В `results.csv` `FAIL` | бенчмарк завершился с ошибкой | `tail -30 results/*/threads_N.log` |
| `./run.sh` очень долго идёт | по умолчанию `NITER=5` и потоки 1 2 4 8 | быстрая проверка: `NITER=1 ./run.sh 8` |

## Известное, но не выясненное

- Запуск OpenVINO с `ONEDNN_VERBOSE` на плате падает с `could not execute a primitive`. Причина не найдена.
  Для замера времени этот режим не используйте.
- Происхождение патчей OpenVINO (правки на плате) автором не подтверждено.
- Часть слоёв ResNet-50 остаётся на `ref`-реализации свёрток: быстрая включается при `inputChannels >= 16` и
  `outputWidth >= 20`. Максимально возможная скорость не исследована.
